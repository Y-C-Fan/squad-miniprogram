把手机放裤袋里，或者拿在手上，点一下开始，剩下的交给它。

灵感来自 [DunDun](https://apps.apple.com/cn/app/dundun-%E6%B7%B1%E8%B9%B2%E8%87%AA%E5%8A%A8%E8%AE%A1%E6%95%B0/id1348285355)（App Store ID 1348285355，作者 haozes）。本项目是**独立实现**，代码、UI、图标全部自写，未使用其任何资源。

| 渠道 | 用户拿到的方式 | 你要付出的 | 覆盖面 |
|---|---|---|---|
| 🌐 网页版 / PWA | 点链接 / 装到桌面 | 无 | 所有手机浏览器 |
| 📱 微信小程序 | 微信搜或扫码 | 个人主体注册 + 实名 + 小程序备案 + 审核 1~7 天 | 微信生态 |
| ⌚ 手环·官方市场 | 手环上搜装 | 开发者实名 + **软著** + **APP 备案** + 快应用审核 | 仅 Vela 手环 |
| ⌚ 手环·侧载 rpk | ADB 或第三方 App 导入 | 无 | 同上，但用户操作成本极高 |

**手环能进官方市场，不是只能侧载。** 事实核对（2026-10）：

- 小米手环 8 Pro / 9 / 9 Pro / 10 跑 **Vela OS**，第三方应用形态是 `.rpk` 快应用。官方分发入口是 **[快应用分发](https://dev.mi.com/xiaomihyperos/quickapp-distribute)**：上传 rpk → 快应用备案 → 审核 → 上架，官方明确写了支持「手机 / 音箱 / 智能穿戴」跨设备分发。
- 但上架门槛跟小米应用商店一致（[应用商店上架要求](https://dev.mi.com/distribute/doc/details?pId=1322)）：**软著**（软著登记证书 / APP 电子版权认证证书 / 软著认证证书，三选一）+ **工信部 APP 备案** + 开发者实名，缺一不可。软著常规办理周期 30~60 工作日。
- 别走错门：`dev.mi.com` 的「手表应用发布」上传的是 **APK**，那是跑 Android 的 Xiaomi Watch，手环要走**快应用**入口。

所以对一个自用的小工具来说，**为上手环市场去办软著 + 备案性价比很低**，而且即使上了，能装的手环机型也只有 8 Pro / 9 / 9 Pro / 10。这个项目的取舍是：**把零门槛的网页版（PWA）做成主入口**，手环版作为技术验证保留在 `band/`。

## 三个必须知道的坑

**① `requiredPrivateInfos: ["accelerometer"]` 不能少**

从基础库 2.21.0 起，`wx.startAccelerometer` 属于微信认定的敏感接口。**不声明的话微信会静默屏蔽它 —— 不报错、不抛异常、只返回空值**，表现就是"点了开始数字永远不跳"，排查起来极其痛苦。`app.json` 里已配好。

同理 `__usePrivacyCheck__` 也要开。授权被拒后微信不允许二次弹窗申请，所以代码里走的是「自定义弹窗 → `wx.openSetting` 引导去设置页」，见 `pages/index/index.js` 的 `showSensorAuthGuide`。

**② 传感器回调里绝对不能 setData**

`interval: 'game'` 是 20ms/次 ≈ 50Hz。每次回调都 `setData` 会把 JS→Native 桥打满，表现为低端机掉帧。圆环进度只喂给 canvas、不参与 wxml 渲染，代码里**没有任何 `setData({ring})`**，并且 canvas 重绘也节流到 30fps（绘制同样在 UI 线程）。网页版同样按 30fps 节流。

**③ 开发者工具里测不出算法准不准**

工具里 accelerometer 是模拟数据。阈值必须用**真机**验证 —— 用线上网页版最方便。详见 docs/LAUNCH.md 第七节。

## 算法是怎么工作的

### 为什么不能直接数波峰

对加速度模长做波峰检测是最直觉的做法，但在实际使用中会崩：

- 走路、抬手、上下楼梯都会产生足以触发阈值的波峰 → **大量误计**
- 站着不动时的传感器抖动会持续产生小峰 → **假计数**
- 深蹲幅度有大有小，固定阈值顾此失彼

### 实际做法：三级处理

**第一级 · 信号拆分**
用 τ=0.10s 的一阶低通把原始三轴加速度拆成两路：

- **重力方向** `ĝ`（单位向量）→ 用于判断设备姿态
- **线加速度** `l = a − ĝ·g` → 用于判断"人是不是真的在发力"

τ=0.10 是实测权衡点：真实 30°/45°/60° 的倾斜，低通后仍保留 95%/94%/95% 的幅度。放到 0.16s 就只剩 87%（阈值会被吃掉一大截），放到 0.05s 又压不住噪。

**第二级 · 主信号二选一**

| 模式 | 适用 | 主信号 | 计算 |
|---|---|---|---|
| `tilt` | 放裤袋 / 绑腿 | 倾角（度） | `acos(ĝ · ĝ₀)`，ĝ₀ 是校准基准 |
| `lift` | 拿在手上 | 向下位移（米） | 线加速度投影到重力轴 → 去偏置 → 泄漏积分两次 → 减慢均值去趋势 |

为什么手持要用位移：手拿手机时设备基本不转，倾角几乎不变，必须换信号。

**第三级 · 施密特触发状态机**

```
top ── signal ≥ enter ──> bottom ── signal ≤ exit ──> top  (+1)
        └─ 停留超 maxDownMs ─────────────────────> top  (作废)
```

双阈值（enter/exit）形成滞回带，避免信号在阈值附近抖动时反复触发。只有同时满足下面 4 个条件才算一次：

1. 下沉时长 ≥ `minDownMs`（太快的不算）
2. 下沉期间线加速度峰值 ≥ `minMotion`（慢吞吞挪一下的不算）
3. 距上次计数 ≥ `minGapMs`（手抖防连击）
4. 未超时（蹲下去坐下的那一趟会被作废）

**校准为什么要判"静止"**

按「开始」时会锁一个基准重力方向 ĝ₀。如果人在下蹲中途点开始，ĝ₀ 就被带歪了，之后每一蹲的相对角度都被压扁 —— 仿真里 45° 的动作只能测到 24°，**准确率直接砍半**。所以校准同时要求「时长 ≥ 700ms」且「整个窗口线加速度 < 0.5」，一直动则最多等 5 秒。

**零点漂移的补偿**

手机在口袋里会慢慢滑动，基准会逐渐失真。做法是在「站姿 + 完全静止」时让 ĝ₀ 以 τ=15s 极慢地跟随当前重力。关键是必须同时约束线加速度很小 —— 否则训练过程中基准会被平均值吃掉，信号幅度越蹲越小（这个坑在开发中真实踩到过）。

### 灵敏度档位

低通会让幅度缩水约 5%，所以阈值留了余量，不能贴着真实幅度定：

| 档位 | 触发门槛（真实幅度） | 说明 |
|---|---|---|
| 低 | ≥ 30° | 几乎不误计，适合幅度大的人 |
| 中 | ≥ 22° | **推荐**，常规深蹲 |
| 高 | ≥ 12° | 轻微屈膝也会算，容易多算 |

## 自检

算法和业务逻辑都有离线自检脚本，用 Node 跑，不需要开发者工具：

```bash
node tools/simulate.js          # 32 项：两种模式 × 三档灵敏度 × 干扰场景
node tools/test-logic.js        # 36 项：卡路里 / 连续天数 / 热力图 / 勋章 / 存储
node tools/test-calibration.js  # 14 项：校准静止判定 / 倾角基准 / 零点漂移
node tools/test-remote.js       # 37 项：远端阈值覆盖的接受/拒绝/整体回滚
node tools/build-web.js         # 重新生成 web/index.html
node tools/make-band-config.js  # 重新生成 web/band-config.json（手环远端参数）
node tools/sync-band.js --check # 校验手环算法副本与 utils/ 一致
python tools/make-icons.py      # 重新生成 PWA 图标（纯标准库，不用装 Pillow）
```

`simulate.js` 用合成加速度数据（含噪声）喂给探测器，覆盖 25°~60° 幅度、1.2s~3.0s 周期、以及「纯噪声」「小幅晃动」等不该计数的干扰场景。**改算法后先跑这两个脚本**，比手测靠谱得多。

## 平台限制（已做兜底，但请知悉）

1. **切后台 / 锁屏会丢传感器回调**。小程序无后台保活能力。代码里 `onHide` 会自动暂停并提示，不会静默丢数据；训练时也开了 `keepScreenOn`。
2. **拿不到实时心率**。心率需要设备级传感器支持，小程序 API 不提供。这部分留给手环版。
3. **语音报数需自行注册 TTS**。`utils/audio.js` 预留了接口，两种接法（CDN 预录音频 / 微信同声传译插件）都在文件头注释里。未注册时只弹数字 Toast。
4. **语音插件需要正式 AppID**，测试号加不了插件。
