# 上线手册

> 从「代码写完」到「微信里能搜到」的完整路径，以及每个环节的坑。

---

## 一、先看清楚：谁能做什么

| 步骤 | 谁能做 | 说明 |
|---|---|---|
| ① 注册小程序账号 | **只有你** | 身份证实名 + 管理员微信扫码，AI 无法代劳 |
| ② 填《用户隐私保护指引》 | **只有你** | MP 后台提交，要审核 |
| ③ 开发者工具上传代码 | 你扫码登录后可以 | 需要你本机操作一次 |
| ④ 提交审核 | **只有你** | 管理员扫码确认，AI 无法代劳 |
| ⑤ 发布 | 自动 | 你点确认后微信自动放行 |

**实测耗时**：注册约 5 分钟，隐私指引审核 1 小时~数小时，代码审核通常 1~7 天（个人主体小程序）。

---

## 二、注册（5 分钟）

1. 打开 <https://mp.weixin.qq.com> → 右上角「立即注册」→ 选**小程序**
2. 填一个没被占用的小程序名称（名字唯一，**想好再填，改名每年只有 2 次机会**）
3. 主体类型选**个人**（个人主体不能开通支付、不能收集手机号，但本项目不需要）
4. 用你的**管理员微信**扫码，完成身份证 + 实名认证（人脸识别）
5. 登记后进入后台，首页就能看到 **AppID**

> ⚠️ 个人主体小程序：不能加「支付」「手机号」等能力。本项目纯本地存储，**完全不受影响**。

---

## 三、填《用户隐私保护指引》（最容易卡住的一步）

**后台路径**：`mp.weixin.qq.com` → 设置 → 基本设置 → **用户隐私保护指引** → 更新

需要填的项：

| 勾选项 | 填写 |
|---|---|
| 设备信息 → 传感器数据 | 使用目的：*用于识别深蹲动作并自动计数* |
| 用户数据 → 体重（可选） | 本项目只用体重估算卡路里，**存本机不上传**，可以不勾 |
| 其他 → 自定义 | 建议勾「加速度传感器」，理由同上 |

**填写要点**：
- 申请理由必须写清**具体用途**，写「优化体验」这类空话会被打回
- 提交后要等审核，**通过后才能正常调用接口**
- 每次修改都会重新触发审核

### 代码里已配好的部分

`app.json` 已经写了：

```json
"requiredPrivateInfos": ["accelerometer"],
"__usePrivacyCheck__": true
```

**为什么这两行不能少**：从基础库 2.21.0 起，`wx.startAccelerometer` 属于微信认定的敏感接口。**不声明的话微信会静默屏蔽该 API —— 不报错、不抛异常，只返回空值**，表现就是"点了开始数字永远不跳"，极难排查。这个坑我在开发时查证过，提前写上了。

代码里也做了授权失败兜底（`pages/index/index.js` 的 `showSensorAuthGuide`）：用户拒绝授权后微信不允许二次弹窗，所以走自定义弹窗引导去设置页手动开启。

## 四、开发者工具上传

1. 下载安装 <https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
2. 导入项目 → 选仓库根目录
3. **AppID 填你刚注册拿到的**（替换 `project.config.json` 里的 `touristappid`）
4. 点「上传」→ 填版本号 `1.0.0` + 项目备注

> 小程序基础库建议选 **3.5.0 以上**，`canvas type="2d"` 圆环需要 2.9.0+。

---

## 五、提交审核

**后台路径**：版本管理 → 开发版本 → 选刚上传的版本 → 提交审核

审核备注建议直接写：

```
深蹲自动计数工具。
- 全部数据仅存本机 wx.Storage，无网络请求、无服务器、无用户账号
- 唯一使用的敏感接口为加速度计，用于识别深蹲动作
- 不含广告、不含内购、不含诱导分享
```

**常见驳回原因自查**：

| 驳回理由 | 本项目是否涉及 | 应对 |
|---|---|---|
| 隐私指引不完整 | 需按上表补全 | 见第三节 |
| 诱导分享 | ❌ 不涉及。分享入口在胶囊菜单「···」里，右上角没有诱导性按钮 | 保持现状即可 |
| 功能不完整 | 需确保三个页面都能正常走通 | 真机把训练/数据/我的都点一遍 |
| 类目不符 | 选「体育-健身」 | 提交时同步改服务类目 |

## 六、发布

审核通过 → 版本管理 → 正式版本 → 点「发布」。

建议**先发体验版**（开发者 → 体验版）给自己和 1~2 个朋友用 3~5 天，确认算法在真实人体上够稳再发正式版。原因见下一节。

---

## 七、上线前必须做的实测

⚠️ **这是本项目最大的未知数**：`utils/squat-detector.js` 的阈值全部来自合成数据仿真，**从没在真人身上跑过**。

上线前务必走完这个 checklist：

1. **开发者工具里是模拟数据，不算数** —— 必须用「真机预览」扫码在真手机上测
2. 打开 `我的 → 显示调试信息`
3. 分别测两种摆放：
   - 手机放裤袋 → 设置选「口袋」
   - 手机拿手上 → 设置选「手持」
4. 每种摆法蹲 20 个，对一下实际次数
5. **数少了** → 灵敏度往高档调
6. **数多了 / 站着也跳** → 灵敏度往低档调；或站定时手别乱动
7. 蹲得慢（3 秒一个）也要测，最容易漏计

> 如果三种灵敏度都别扭，问题大概率不在阈值而在**检测方式选错了** —— 手拿着手机却选了「口袋」模式，倾角根本不变，必然数不出来。

## 八、获客

工具类小程序没有自然流量，唯一的增长入口是**分享**。代码里已经做好的：

- `onShareAppMessage` —— 标题会带真实数据（「我蹲了 128 个深蹲，来比比谁多」）
- `onShareTimeline` —— 朋友圈分享，带连续打卡天数
- tabBar 三个页都有图标，不点「···」也能看到入口

**上线后的获客动作**（按性价比排序）：

1. **自用先跑通**，连续用 7 天，把连续打卡天数养出来 —— 连续天数是这类产品的核心留存钩子
2. **朋友圈/小红书发"对比"内容**：手动数 vs 自动数的对比视频，比讲功能有用
3. **搜索流量**：名字要含「深蹲」「计数」等搜索词，微信搜一搜能吃到
4. **不推荐做裂变**（分享得次数、邀请得奖励）—— 工具类小程序做这个容易被判诱导分享，直接下架

---

## 九、隐私合规自查

本项目的合规优势是**零数据采集**：

- ✅ 无网络请求（`wx.request` 一次都没调）
- ✅ 无用户账号、无 openid 获取
- ✅ 数据只写 `wx.Storage`，卸载即清除
- ✅ 唯一敏感接口是加速度计，理由充分

审核时如果后台有「未收集用户信息」选项，**选它**。

## 十、常见问题

**Q：数字一直不跳，但没报错？**
A：99% 是加速度计权限问题。检查 ① 隐私指引是否审核通过 ② 真机测试而非模拟器 ③ `requiredPrivateInfos` 是否声明。这是最典型的静默失败。

**Q：切后台回来后数据乱了？**
A：正常。平台限制，小程序退后台传感器回调会停。代码里 `onHide` 会自动暂停，不会静默丢数。

**Q：iOS 上不准？**
A：iOS 传感器采样率限制（`interval:'game'` 实际约 20~50ms），且系统会对传感器数据做平滑。可以尝试把 `page` 里的检测方式调成「手持」。

**Q：能加心率吗？**
A：小程序拿不到实时心率，这是设备级 API 限制。只有手环端能做。
